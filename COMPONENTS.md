**Версия:** 1.0 (draft)
**Дата:** 2026-07-06
**Статус:** спецификация утверждена, реализация не начата
**Связанные задачи:** FEAT-5 (VLM/Florence-2 — пилотный компонент), в перспективе FEAT-4 (STT видео)

---

## 1. Мотивация

Тяжёлые ML-функции (Florence-2 ≈ torch + веса, суммарно гигабайты) невозможно
упаковать в основной exe (~65 МБ onefile): сборка раздувается, а Florence-2
вообще не работает во frozen-окружении (известное ограничение проекта).

**Решение (вариант Б, утверждён 2026-07):** тяжёлые функции выносятся в
*компоненты* — отдельные PyInstaller-сборки со своим Python-окружением внутри.
Главное приложение скачивает их по требованию и вызывает как subprocess.

Выгоды: главный exe остаётся лёгким; версии torch изолированы; падение
компонента не роняет GUI; компоненты обновляются независимо от релизов Розитты.

## 2. Термины и структура

**Компонент** — zip-архив с onedir-сборкой PyInstaller (НЕ onefile — меньше
ложных срабатываний антивирусов и нет распаковки в %TEMP% при каждом запуске).

Внутри архива:

```
RozittaVLM/
├── RozittaVLM.exe          # CLI-воркер (точка входа)
├── _internal/              # стандартный onedir PyInstaller
└── component.json          # локальный манифест (см. §3)
```

**Расположение на диске пользователя** (портативность — философия проекта,
всё лежит рядом с exe, как config и session):

```
<папка с RozittaParser.exe>/
└── components/
    └── vlm/
        └── 1.0.0/
            └── RozittaVLM/...
```

Путь переопределяется в `config.json` полем `components_dir` (на случай
маленького диска). Модели HuggingFace компоненты качают в общий
`~/.cache/huggingface` (стандарт ML-стека, общий с faster-whisper).

## 3. Манифесты

### 3.1 Удалённый реестр `components_registry.json`

Один JSON в GitHub Releases репозитория (asset у релиза-«полки» компонентов,
обновляется workflow'ом). Главное приложение скачивает его при обращении
к функции, требующей компонент.

```json
{
  "registry_version": 1,
  "components": {
    "vlm": {
      "latest": "1.0.0",
      "versions": {
        "1.0.0": {
          "protocol": 1,
          "min_app_version": "1.7.3",
          "size_bytes": 1930000000,
          "sha256": "<hex>",
          "urls": [
            "https://github.com/Nynchezyabka/RozittaParser/releases/download/components-vlm-1.0.0/RozittaVLM-win64-1.0.0.zip"
          ]
        }
      }
    }
  }
}
```

- `urls` — список: [0] основной, далее зеркала (GitHub из РФ бывает медленным;
  зеркало добавим, когда появится — поле заложено сразу).
- `protocol` — версия CLI-протокола (§4). Приложение отказывается запускать
  компонент с protocol новее, чем оно знает.

### 3.2 Локальный `component.json` (внутри архива)

```json
{ "name": "vlm", "version": "1.0.0", "protocol": 1, "entry": "RozittaVLM.exe" }
```

Наличие файла = маркер успешной распаковки (пишется последним при установке?
Нет — он в архиве; маркер успешной установки — файл `.installed`, который
ComponentManager создаёт ПОСЛЕ проверки sha256 и полной распаковки).

## 4. CLI-протокол воркера (protocol=1)

Общие правила для всех компонентов:

```
RozittaVLM.exe --task <файл-задания.json> --result <файл-результата.json>
```

- **Задание и результат — файлы**, не stdin/stdout (кириллические пути и
  кодировки консоли Windows — минное поле; файлы UTF-8 надёжнее).
- **stdout** — только строки прогресса, по одной на событие:
  `PROGRESS <done> <total>` (парсится главным приложением для прогресс-бара).
- **stderr** — свободный лог для отладки, приложение пишет его в rozitta.log.
- **Коды возврата:** 0 — успех (result-файл записан полностью);
  1 — ошибка задания (детали в result-файле, поле `error`);
  2 — фатальная ошибка окружения (result может отсутствовать).
- Воркер обязан быть **идемпотентным**: повторный запуск того же задания
  не должен ломаться (перезапись result-файла допустима).
- Никакого Qt внутри компонентов. Никакой записи в БД Розитты — компонент
  чистая функция «файлы → JSON». Запись в SQLite делает только главное
  приложение (не плодим участников DB-LOCK-2).

### 4.1 Задание VLM (пилот, FEAT-5)

```json
{
  "protocol": 1,
  "task": "describe_images",
  "model": "base",              // "base" | "large"
  "language": "ru",
  "images": [
    "D:/.../output/Чат/photo/12345.jpg",
    "D:/.../output/Чат/photo/12346.jpg"
  ]
}
```

### 4.2 Результат VLM

```json
{
  "protocol": 1,
  "ok": true,
  "descriptions": {
    "D:/.../photo/12345.jpg": "Терраса с деревянным настилом, вид на сад.",
    "D:/.../photo/12346.jpg": null
  },
  "errors": { "D:/.../photo/12346.jpg": "corrupt image" },
  "model": "base",
  "elapsed_sec": 218.4
}
```

`null` в descriptions + запись в errors — файл пропущен, батч не падает
из-за одной битой картинки.

## 5. ComponentManager (главное приложение)

### 5.1 Размещение кода (Qt-изоляция — правило проекта)

```
core/components/__init__.py
core/components/manager.py     # ComponentManager — БЕЗ Qt (чистый Python)
features/vlm/ui.py             # VlmWorker(QThread) — весь Qt здесь
features/vlm/api.py            # формирование заданий, разбор результатов, запись в БД
```

### 5.2 API ComponentManager (минимум, ничего «на вырост»)

```python
class ComponentManager:
    def __init__(self, components_dir: Path, registry_url: str): ...

    def get_installed(self, name: str) -> Optional[InstalledComponent]:
        """Ищет components/<name>/<version>/.installed, максимальная версия."""

    def fetch_registry(self) -> dict:
        """Скачивает components_registry.json. Таймаут 15с, исключения наружу."""

    def download(self, name: str, version: str, info: dict,
                 progress_cb: Callable[[int, int], None],
                 cancel_flag: Callable[[], bool]) -> Path:
        """Качает zip во временный файл (стриминг, chunk 1 МБ, progress_cb(done, total)),
        проверяет sha256, распаковывает, создаёт .installed, возвращает путь.
        При несовпадении sha256 / отмене — удаляет всё за собой."""

    def run(self, comp: InstalledComponent, task: dict,
            progress_cb, cancel_flag, timeout_sec: Optional[int]) -> dict:
        """Пишет task в temp-файл, запускает entry через subprocess.Popen,
        читает stdout построчно (PROGRESS ...), по завершении читает result-файл.
        cancel_flag → terminate() процесса. Возвращает dict результата."""
```

`InstalledComponent` — dataclass: name, version, protocol, entry_path.

Замечание по потокам: `manager.py` синхронный и блокирующий — это нормально,
потому что вызывается он только из QThread-воркера (`VlmWorker`), по той же
схеме, что ParseWorker/ExportWorker. Внутри воркера subprocess, наружу — сигналы
`log_message(str)`, `progress(int)`, `finished(object)`, `error(str)`,
`character_state(str)` (стандартный набор из CLAUDE.md).

### 5.3 UX-поток первого включения функции

1. Пользователь включает тумблер «Описывать изображения (VLM)» в настройках.
2. Компонент не установлен → диалог: «Функция требует компонент
   „Распознавание изображений“ (~1.9 ГБ, разово). Скачать?» [Скачать] [Отмена].
3. Скачивание с прогрессом в стандартной панели, кнопка отмены.
4. Ошибка сети/хеша → понятное сообщение + предложение повторить.
5. После установки функция работает без вопросов; тумблер запоминается в config.

## 6. Обработка ошибок и краевые случаи

| Случай | Поведение |
|---|---|
| Нет сети при fetch_registry | Сообщение «Не удалось получить список компонентов», функция выключается, парсинг продолжается без неё |
| sha256 не совпал | Удалить скачанное, предложить повторить (возможен битый прокси/зеркало) |
| Отмена скачивания | Удалить temp-файл, тумблер вернуть в off |
| Компонент завис | timeout_sec на задание (VLM: 60с × число картинок, минимум 600с) → terminate + ошибка в лог |
| result-файл отсутствует при коде 0 | Считать фатальной ошибкой компонента, в лог stderr |
| protocol новее известного | «Обновите Rozitta Parser» — не запускать |
| Антивирус удалил exe компонента | get_installed видит .installed без entry → статус «повреждён», предложить переустановку |

## 7. CI: сборка и публикация компонентов

Отдельный workflow `build_component_vlm.yml` (запуск вручную, по тегу
`components-vlm-X.Y.Z`):

1. PyInstaller onedir-сборка воркера (свой spec: `rozitta_vlm.spec`).
2. Вложить `component.json`.
3. Zip → `RozittaVLM-win64-X.Y.Z.zip`, посчитать sha256.
4. Создать/обновить release `components-vlm-X.Y.Z`, приложить zip.
5. Обновить `components_registry.json` на релизе-полке (руками на первом
   этапе — автоматизацию не строим, пока компонент один; simplicity first).
