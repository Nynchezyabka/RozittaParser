# ТЗ: пресет экспорта «🧠 База знаний для ИИ» (Knowledge Base Export)

## Зачем (контекст для разработчика)

Сейчас пресет «🤖 Для нейросети» выгружает Markdown-чанки, но пользователю,
чтобы реально задавать вопросы по архиву через ИИ-инструменты (Claude Code,
NotebookLM, AnythingLLM), приходится вручную: составлять таблицу «какой файл
к чему относится», прописывать метаданные, писать инструкцию для ИИ.
Это отсекает всех нетехнических пользователей.

Вся нужная информация (посты, комментарии, авторы, даты, связи медиа
с сообщениями) уже есть в SQLite-базе парсера в момент экспорта.
Задача — генерировать «обвязку» автоматически.

Терминология в UI: НЕ использовать слово «корпус». Пользовательское название
пресета — «🧠 База знаний для ИИ». В подсказке: «Архив с оглавлением и
инструкцией для нейросети — можно сразу задавать вопросы через ИИ-инструменты».

## Что должно генерироваться при экспорте

Всё складывается в папку выгрузки чата (`output/<название чата>/`).
Существующая логика экспорта файлов НЕ меняется и файлы НЕ переименовываются —
добавляются только новые артефакты.

### 1. `00_Оглавление.md` — главная точка входа

Markdown-таблица всех постов канала (или тем форума / дней переписки —
по типу чата), отсортированная хронологически. Колонки:

| № поста | Дата | Автор | О чём (первая строка) | Файлы |

- «Начало поста» (не называть колонку «Тема» — честность формулировки):
  эвристика из трёх правил, проверена на реальном канале:
  1) если в первых 6 непустых строках есть строка, начинающаяся с
     «Выпуск №?N» — взять её;
  2) иначе первая строка, не являющаяся приветствием
     (не начинается с «Уважаем/Дорог/Привет/Здравств/🌟») и длиннее 15 символов;
  3) иначе первая непустая строка как есть.
  Разметку markdown снять, обрезать до 120 символов. Если текста нет
  (только медиа) — тип медиа: «[видео]», «[фото]», «[голосовое]».
- «Файлы» — относительные кликабельные ссылки на все артефакты поста:
  файл поста/комментариев, медиафайлы, транскрипции (если найдены,
  см. п. 5). Пробелы в путях экранировать %20.
- В шапке файла: название чата, период, число постов/сообщений/участников,
  дата генерации, одна строка «Этот файл — оглавление архива, начинай
  поиск с него».

### 2. YAML-шапки в каждом экспортируемом .md

В начало каждого Markdown-файла (пост, комментарии, чанк) добавлять:

```yaml
---
chat: <название>
post: <номер сообщения>             # если применимо
date: <YYYY-MM-DD>
author: <имя>                       # для постов канала
type: post | post_with_comments | dialog | transcript
comments_count: <N>                 # для файлов с обсуждениями
---
```

Ключи по-английски (совместимость с внешними инструментами и будущей
англоязычной версией), значения — на языке чата.
Если шапка уже есть (повторный экспорт) — не дублировать.

### 3. `ИНСТРУКЦИЯ_ДЛЯ_ИИ.md` + копии `CLAUDE.md` и `AGENTS.md`

Один генерируемый текст, сохраняемый под тремя именами (Claude Code читает
CLAUDE.md, другие агенты — AGENTS.md, человек поймёт по русскому имени).
Шаблон с подстановками из метаданных чата:

- что это за архив (название, период, тип чата, число сообщений);
- структура папок и схема имён файлов ЭТОЙ выгрузки; типы полок
  (`chat_archive` — первичный источник, `reference_material` — справочные
  материалы, добавленные пользователем);
- указание начинать любой поиск с `00_Оглавление.md`;
- **режимы работы** (фиксированный блок; режим по умолчанию — Архивариус,
  переключение по явной формулировке пользователя):
  - **Архивариус** — отвечать только по полкам архива; каждый тезис
    подтверждать ссылкой на файл и номер поста/дату; если информации нет —
    прямо сказать об этом; не смешивать текст автора поста с мнениями
    комментаторов.
  - **Консультант по материалам** («посоветуй на основе книги/методики…») —
    рекомендации только из справочных полок с указанием источника;
    факты о ситуации — из полок архива и/или со слов пользователя,
    всегда с пометкой, что откуда; связка теории с ситуацией явно
    помечается как применение, а не как факт.
  - **Свободный советник** («дай общий совет…») — общие знания модели
    разрешены, но факты об архиве — по-прежнему только из архива,
    а общие рекомендации явно помечаются как не основанные на материалах.
- **типы задач** (работают в любом режиме, наследуя его правила
  достоверности): вопрос-ответ; подборка (извлечь всё по критерию);
  аналитика (вычисления над архивом: динамика, доли, паузы — приводить
  числа, не впечатления); составление (дайджест, отчёт, чек-лист —
  каждый факт в итоговом тексте прослеживается до источника);
- **деликатные темы** (переписка о личных отношениях, дневники,
  психологические материалы): разделять уровни «факт → контекст →
  гипотеза» и помечать гипотезы как гипотезы; не выносить суждений
  о мотивах и состояниях реальных людей; при работе с методиками —
  передавать материал автора, не выступая терапевтом;
- совет искать по основам русских слов (морфология);
- один и тот же пост может встречаться в нескольких срезах-полках —
  считать повторы одним источником;
- запрет переименовывать/изменять файлы архива.

### 4. `archive_passport.json` (паспорт архива)

Машиночитаемое описание для будущего Библиотекаря и внешних инструментов:
название чата, тип, период, счётчики (посты, сообщения, участники, медиа),
версия схемы, схема имён файлов, список полок с их типами
(`chat_archive` / `reference_material`), список сгенерированных артефактов,
дата генерации, версия парсера.

Для личных диалогов и групп без постов оглавление дополняется
**хронологической картой** (вычисляется из базы, без ИИ): сообщений
по месяцам, доля каждого участника, паузы длиннее 14 дней, периоды
всплесков. Это опора для задач типа «аналитика».

### 5. Связывание транскрипций и медиа с постами

- При экспорте искать папку `transcripts` (создаётся Rozitta Transcriber)
  рядом с медиа; сопоставлять транскрипции медиафайлам по имени
  (`<имя медиа>.md`), а медиа — постам по данным из базы.
  Найденные транскрипции включать в «Файлы» оглавления и получать YAML-шапку.
- Для медиа из комментариев прописывать в оглавлении и YAML родительский
  пост (база знает связь сообщение → пост обсуждения).

### 6. UI

- Новый пресет «🧠 База знаний для ИИ» рядом с существующими — включает
  текущие настройки пресета «Для нейросети» + генерацию артефактов 1–5.
- В существующий пресет «🤖 Для нейросети» изменения не вносить.
- Чекбокс в настройках экспорта «Создать оглавление и инструкцию для ИИ»,
  чтобы добавлять обвязку к любому режиму экспорта.
- В окне «Проверьте перед стартом» показывать, что будет создано.

## Архитектурная поправка: сборка — отдельная операция, не режим экспорта

Пользователь делает НЕСКОЛЬКО выгрузок одного чата (полный архив,
сообщения участника, диапазон дат, чанки). База знаний — сборка НАД ними:

- Операция «Собрать/обновить базу знаний» запускается по кнопке для папки
  чата и сканирует все выгрузки в `output/<чат>/`.
- Каждая выгрузка-срез — раздел («полка») оглавления с описанием среза
  (что выгружено, фильтры, период).
- В `ИНСТРУКЦИЯ_ДЛЯ_ИИ.md` явно описывать полки и указывать: один и тот же
  пост может встречаться в нескольких срезах — считать повторы одним
  источником.
- В `archive_passport.json` — состав сборки: какие срезы, когда выгружены,
  какими настройками.
- Пересборка идемпотентна; кнопка «Обновить» после каждой новой выгрузки.
- Для простого сценария: чекбокс «Собрать базу знаний после экспорта»
  (включён в пресете «🧠 База знаний для ИИ») — тогда пользователь
  не обязан знать про отдельную операцию.

## Нефункциональные требования

- Кодировка всех артефактов UTF-8 (с учётом Windows).
- Идемпотентность: повторный экспорт перезаписывает оглавление/инструкцию/
  паспорт и не дублирует YAML-шапки.
- Генерация не должна заметно замедлять экспорт (данные уже в базе,
  допустимо +секунды, не минуты).
- Никаких сетевых запросов и LLM-вызовов: только детерминированная
  генерация из базы.
- Все новые строки UI — через существующий механизм локализации.

## Критерии приёмки

1. Выгрузка канала с комментариями пресетом «База знаний для ИИ» создаёт:
   оглавление со ссылками на все посты, инструкцию (3 файла), паспорт,
   YAML-шапки во всех .md.
2. Все ссылки в оглавлении открываются (файлы существуют, пути верны),
   включая пути с пробелами и кириллицей.
3. Если рядом с медиа есть папка transcripts от Rozitta Transcriber —
   транскрипции попадают в оглавление и связаны с правильными постами.
4. Повторный экспорт не ломает и не дублирует артефакты.
5. Сценарий конечного пользователя: выгрузить чат → открыть папку
   в Claude Code → задать вопрос «о чём пост N» → получить ответ
   со ссылкой на файл. Ни одного ручного шага между выгрузкой и вопросом.
6. Экспорт личной переписки (без постов) также генерирует оглавление
   (по дням/месяцам) и инструкцию — пресет не падает на чатах без постов.

## Вне рамок этой задачи

- Никакого встроенного чата с ИИ (это отдельный продукт «Библиотекарь»).
- Никаких эмбеддингов, векторных индексов, чанкинга сверх существующего.
- Автоопределение тем/циклов постов через LLM (этап 3 роадмапа).
