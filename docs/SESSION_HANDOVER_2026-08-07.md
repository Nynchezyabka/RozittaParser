### `requirements.txt` не читался pip на русскоязычной Windows

Попытка догнать окружение упёрлась в следующий слой:

```
UnicodeDecodeError: 'charmap' codec can't decode byte 0x98 in position 330
decoding with 'cp1251' codec failed
```

Байт `0x98` — вторая половина буквы «И» в комментарии «База знаний для ИИ».
`pip` (`_internal/utils/encoding.py`, `auto_decode`) выбирает кодировку по
порядку: BOM → PEP 263 coding-cookie в первых двух строках → **локаль
системы**. В файле не было ни того, ни другого, поэтому на Windows с русской
локалью он читался как cp1251, где `0x98` не определён.

На Linux и на Windows с UTF-8-локалью файл читается нормально — поэтому баг
невидим в контейнерах и на CI, но **ломает установку зависимостей у любого,
кто клонирует репозиторий на русскоязычной Windows**. То есть свежий клон
проекта до этой правки был неустанавливаем.

Фикс (`patch_requirements_encoding.py`): строка `# -*- coding: utf-8 -*-`
первой строкой файла. Выбрана вместо BOM осознанно — видна в тексте, не
создаёт невидимых байтов, git-diff остаётся читаемым.

**Соседи проверены, случай единичный:** `pytest.ini` тоже с кириллицей, но
его читает `iniconfig` с жёстко заданным `encoding="utf-8"`;
`config_modern.json` читает наш `config.py`, тоже с явной кодировкой.
Уязвим оказался только `requirements.txt` — единственный текстовый файл с
кириллицей, который разбирает сторонний инструмент, полагающийся на локаль.

### Импорт tdata: ошибки opentele2 утекали мимо всех обработчиков

Последний тест, оставшийся красным после доустановки зависимостей:

```
FAILED TestImportFromTdata::test_tdata_path_not_exists
  — opentele2.exception.TFileNotFound (ожидался AuthError)
```

`import_from_tdata()` обещает в docstring поднимать `AuthError` и имеет для
этого `except Exception as exc: raise AuthError(...)`. Но **`OpenTeleException`
унаследован напрямую от `BaseException`, минуя `Exception`** — таких классов
в библиотеке **27**, включая самые частые у пользователя: `TFileNotFound`
(не та папка), `TDataWrongPasscode` (неверный пароль), `TDesktopNotLoaded`
(Telegram Desktop не закрыт), `TDataInvalidCheckSum` (повреждённая tdata).

Последствие серьёзнее непойманного исключения: `TdataImportWorker.run()` в
`features/auth/ui.py` тоже ловит только `Exception`. Значит сигнал `error` не
испускается, `character_state("error")` не испускается — интерфейс остаётся
висеть в «🖥️ Импорт сессии из Telegram Desktop...» **навсегда, без единого
сообщения**. Пользователь выбрал не ту папку и получил молчаливое зависание.

Почему не ловилось раньше: без установленного opentele2 функция уходит в
ранний `raise AuthError("opentele2 не установлен")` и до реального кода не
доходит. Баг проявляется только там, где библиотека есть — то есть у
пользователей, а не в тестовом окружении.

Фикс (`patch_opentele_baseexception.py`): ловить `OpenTeleException` явно,
рядом с `Exception`. **Не** `except BaseException` — это проглотило бы
`KeyboardInterrupt`, `SystemExit` и `asyncio.CancelledError`, сломав отмену
async-задач.

**Остаётся хрупкость:** `TdataImportWorker.run()` по-прежнему ловит только
`Exception`. Сейчас этого достаточно, потому что источник заткнут, но любое
будущее исключение мимо `Exception` снова даст молчаливое зависание вместо
ошибки. Стоит подумать о защите в воркере — с аккуратной пере-подачей
`CancelledError` и `KeyboardInterrupt`.

**Вывод про тестовое окружение:** неполная `.venv` не только даёт ложные
падения — она **прячет настоящие баги**. Этот жил в коде незаметно ровно
потому, что opentele2 не был установлен, и ветка с реальной работой не
исполнялась ни разу.

**Что стоит обдумать отдельно:** тестовые зависимости и `pyinstaller` лежат
в одном файле с рантаймовыми. Для сборки `.exe` это лишний вес, и разделение
на `requirements.txt` / `requirements-dev.txt` имеет смысл — но по причине
размера дистрибутива, а не ради воспроизводимости тестов.

**Диагностический приём, который сработал:** имена упавших тестов показывают,
какие патчи применены. Старое имя в списке (`..._three_files_identical`)
значит, что патч не накатан; отсутствие целого файла в списке
(`test_parser_static.py`) значит, что все его тесты зелёные. Быстрее, чем
сверять содержимое файлов.

## 4. Открытая задача с поднятым приоритетом

**N-2 — период и охват в имя файла, 🔴.**

`period_label` при выгрузке «за всё время» — литерал `fullchat`. Две
выгрузки одного чата дают одно имя, вторая затирает первую.

`DELETE FROM messages`, вставка через `INSERT OR REPLACE` по ключу
`(chat_id, message_id, COALESCE(topic_id,0))` — повторный парсинг добавляет
новое и не трогает старое. Сообщения, удалённые в Telegram, остаются в базе
с первого прогона (видно по архиву: 571 пост в июле → 593 в августе).

Что происходит: единственная **внешняя** копия затирается. Для чата с
автоудалением это значит, что при потере `.db` восстановить нечего —
перечитать из Telegram уже невозможно.

Делать вместе с **Р-7** из `EXPORT_NAMING.md` (`fullchat` → `alltime`): обе
правки трогают одну строку сборки имени. Формат — фактический охват из БД
